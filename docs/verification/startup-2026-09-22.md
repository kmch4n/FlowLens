# Startup responsiveness and instance ownership

## Baseline

Read-only source-runtime measurements on the designated PC:

- Import application modules: 0.258 s.
- Import UI modules: 0.162 s.
- Full model integrity validation: 4.338 s.

These are individual warm measurements, not a packaged cold-start benchmark.
The original presenter performed preflight validation before `window.show()`.
The new startup shows the shell and prepares recovery/preflight in a QThread.
No hashing or recovery validation is removed. Ready time still depends on I/O.

## Verification

Synthetic/offscreen tests cover secondary activation, ownership release,
dead-process lock recovery, background failure delivery, visible disabled UI
while recovery is blocked, and default/saved Session selection. Full QApplication
lifecycles run in subprocesses to avoid contaminating other Qt tests.

Full regression result: 1746 passed, 2 skipped. Ruff passed; mypy passed for
172 source/test files. Black formatting and `git diff --check` passed.

Package build and audit passed in `dist/FlowLens`. No physical capture, playback
or model inference was used. Real desktop foreground activation remains subject
to Windows focus-stealing restrictions and is not asserted by offscreen tests.

## Follow-up on 2026-10-03

Closing during startup now keeps the window visible and its event loop alive.
It displays a closing message until startup finishes, then closes. The existing
instance can still be activated while waiting. The shutdown regression and
startup lifecycle tests cover this behavior. Permanently stalled native I/O is
not forcibly terminated; it remains visible rather than becoming a hidden process.

## Concurrent full-integrity checks on 2026-10-04

The ASR and discussion entries now run in a two-worker thread executor after
manifest parsing. Both workers finish before the probe returns its stable
`asr`, `discussion` mapping. All existing path, metadata, size, full SHA-256 and
ASR sidecar checks remain in place, including later session-start validation.

Three read-only source-runtime runs per method on the designated Windows PC used
the installed 1,512,927,867-byte ASR model and 2,497,279,008-byte discussion model.
The sequential reference parsed the same manifest and called the unchanged
per-entry verifier in ASR/discussion order; the concurrent measurement called
`check_required()`. Runs alternated method order (sequential/concurrent,
concurrent/sequential, sequential/concurrent), used the default 1 MiB chunks,
and confirmed both models ready on every run.

| Method | Runs (seconds) | Median | Range |
| --- | --- | --- | --- |
| Sequential reference | 3.721, 3.673, 3.570 | 3.673 s | 3.570-3.721 s |
| Concurrent probe | 2.273, 2.293, 2.289 | 2.289 s | 2.273-2.293 s |

These warm filesystem measurements do not establish packaged cold-start,
shell-visible or controls-ready latency. Concurrent reads can contend for disk
bandwidth, so the observed improvement is not a universal speedup. The runs did
not capture or play audio or perform model inference.

The deterministic concurrency regression first failed on the serial
implementation with a two-party barrier timeout (`BrokenBarrierError`), then
passed with concurrent checks. The local-model test file passed 39 tests,
including missing and checksum-mismatched files for either model while the
other model remains ready.

## Native ownership references

- [QLocalServer](https://doc.qt.io/qt-6/qlocalserver.html): Windows permits multiple
  listeners on one pipe name, so the endpoint alone is not an ownership lock.
- [QLockFile](https://doc.qt.io/qt-6/qlockfile.html): indefinite ownership requires
  disabling age-based stale-lock expiry. Process-based recovery remains enabled.
